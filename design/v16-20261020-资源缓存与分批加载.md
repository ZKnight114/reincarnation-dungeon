## 实际行为

- 正式网页按图片文件内容的 SHA-256 建立 CacheStorage 缓存。图片 URL 对应哈希，缓存对象以哈希作为键；相同内容即使换了 URL 也可复用。
- 更新不会删除整库。图片新增或内容改变才联网取图；已有相同哈希直接返回缓存。
- Vite 构建自动遍历所有正式 PNG 输出，包括样式中的图片，生成资源清单和内含清单的 Service Worker。路径相对于部署目录，支持 GitHub Pages 的 `/reincarnation-dungeon/` 子路径。
- Worker 只处理当前部署目录的图片。HTML、JS、CSS 仍正常由服务器提供，避免资源缓存锁住程序版本。只缓存成功且内容哈希验证通过的响应；404、错误页、内容不符均不入库。
- 保留上一版图片 URL 清单，兼容仍打开上一版程序的页面。已缓存图片继续保留供复用；缓存与公会存档分别存储，不清除玩家进度。
- 页面刷新时完成 Worker 更新检查，安装完即接管图片请求。注册及存储失败自动回退；注册等待最多4秒，不让缓存功能阻止进入游戏。

## 加载顺序

1. 读取当前存档，确认进入首页还是恢复培养、远征等画面。
2. 仅等待当前页面及通用操作素材。新公会首页为29项、1,687,422字节，约1.69 MB；全库188项、9,027,402字节，约9.03 MB。
3. 必要素材完成真实加载和解码后进入游戏。Loading 百分比计算当前必需素材进度，不假装全库已经下载。
4. 其余素材以最多两路并发后台加载。共享队列总并发最多六路，给新页面预留前台槽位；同一图片不重复创建请求。
5. 玩家提前打开尚未准备好的页面时，该页任务优先于后台任务。显示准备提示、暂停培养与战斗推进，素材就绪后再渲染；失败保留重试入口，成功素材无需重载。

首页不再提前渲染隐藏的冒险者列表，以免触发人物图片请求。分层人物仅登记已解码且尺寸正确的部件，当前人物所需六层会在页面出现前准备完整。装备、敌人头像也在原图解码后生成，避免缺图或错误裁切结果被长期缓存。

## 发布与边界

- 仍按现有 GitHub Pages 流程构建并发布完整 dist，玩家浏览器只获取需要的新图。此次未部署，线上需要正常推送后才能使用该功能。
- 缓存需要支持 Service Worker 的安全网页环境（HTTPS、本地 localhost/127.0.0.1 HTTP）。不支持时正常加载图片；开发模式和内嵌图片的离线单文件均跳过注册。
- 单文件离线版目前约22 MB，素材全在 HTML 内，文件更新仍是整包下载；不能将网页资源增量缓存等同于单文件增量更新。
- 浏览器主动清理或回收缓存、无痕环境等情况下需要重新取图。此轮不申请额外持久存储权限，也不将网页代码加入离线缓存，因此不是完整离线 PWA。
